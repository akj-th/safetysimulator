### 위험도 히트맵 (`data/heatmap/`) — ⏸ 보류 (2026-09-07)

> **AURI 화상회의에서 보류로 정해졌습니다.** 면으로 덮으면 어디가 문제인지 짚기 어렵고,
> 격자 점이 낫다는 의견입니다. **코드와 PNG는 지웠습니다가 아니라 그대로 둡니다.**
>
> | | |
> |---|---|
> | 지도 화면 | `index.html` 을 커밋 `ea424ab` 로 되돌려 히트맵 UI 를 뺐습니다 |
> | 남겨 둔 것 | `tools/build-heatmap.mjs` · `tools/lib/geotiff.mjs` · `tools/lib/png.mjs` · 서버 화이트리스트 한 줄 |
> | **지운 것** | `data/heatmap/` PNG 287장 + index.json (**19MB**) — 저장소 용량·배포 속도 때문 |
> | 되살리려면 | `npm run heatmap --prefix tools` 로 PNG 를 다시 만들고, `index.html` 의 히트맵 부분을 되돌리기 전 것으로 넣으면 됩니다 (둘 다 git 이력에 있음) |

⚠️ 원본 TIF(`data/raw/gis_0901/density/`, 6.6GB)가 있어야 다시 만들 수 있습니다. 저장소에는 없습니다.

아래는 만들 때의 기록입니다.

강원대가 QGIS로 만든 커널밀도 분석 결과를 지도에 얹습니다.
**밀도값은 우리가 다시 계산하지 않습니다** — 재계산하면 사전진단서에 실린 히트맵과 다른 그림이 나옵니다. 축소·색칠·좌표 계산만 합니다.

| | |
|---|---|
| 원본 | `data/raw/gis_0901/density/` — **6.6GB**, 🔴 커밋 금지 |
| 결과 | `data/heatmap/*.png` 287장 — 커밋 대상 |
| 해상도 | 원본 10m → 4배 축소 **40m** (`SHRINK`) |
| 색 기준 | 그 지자체·그 분야 안의 **99분위**를 만점 (`TOP_QUANTILE`) |
| 색 방식 | **흰색 → 분야 색** 그래디언트 + 투명도 (`COLOR_GAMMA` · `ALPHA_FULL_AT`) |
| 용량 | PNG 287장 **18.2MB** |

**⚠️ 원본이 두 형식으로 섞여 있습니다.** 헤더를 직접 확인한 값입니다.

| 폴더 | 자료형 | 압축 | NoData |
|---|---|---|---|
| `교통사고_최종` | float64 | 없음 | **−3.4e38 (음수)** |
| 나머지 6개 분야 | float32 | **LZW** | +3.4e38 (양수) |

NoData 부호가 반대라 한쪽 기준만 쓰면 다른 쪽이 새까맣게 나옵니다. **절댓값으로 판정**합니다. LZW는 TIFF 방식(MSB 우선·코드폭 조기 증가)으로 직접 구현했고, 안동 교통사고_구급의 99분위 103.22·최대 304.32가 AURI 확인값과 일치해 검증했습니다.

**⚠️ 교통사고는 `교통사고_최종`(TrafficRisk)을 씁니다.** `density/설명.txt`가 "구급 + 다발지역을 합친 최종"이라고 명시하기 때문입니다. 다만 이 파일은 **0~1로 정규화된 위험지수**라 다른 분야(원시 밀도값)와 성격이 다릅니다. 분야별로 따로 정규화하므로 화면에서는 문제가 없지만, 값을 직접 비교하면 안 됩니다. 바꾸려면 `build-heatmap.mjs`의 `FOLDER.traffic` 한 줄입니다.

**화면**: 레이어 목록 맨 위가 **종합 위험도 · 위험도 히트맵** 두 줄입니다.

히트맵은 아래 7개 분야의 **표시 방식을 바꾸는 스위치**입니다.

| 히트맵 | 7개 분야 | 종합 위험도 |
|---|---|---|
| 꺼짐 | 격자 **점** | 점 |
| 켜짐 | 밀도 **면** (점은 감춤) | 점 (그대로) |

점과 면을 함께 켜면 서로를 가려 아무것도 읽을 수 없어 **둘 중 하나만** 올립니다. 종합 위험도는 히트맵이 없는(우리가 계산한) 레이어라 언제나 점입니다.

켠 분야의 **PNG 한 장만** 그때 내려받습니다(287장을 미리 받지 않습니다). 투명도 슬라이더 기본 60%.

⚠️ 히트맵이 없는 지자체로 옮기면 스위치가 자동으로 꺼집니다 — 켜진 채로 두면 점도 면도 없어 지도가 텅 빕니다.

**색은 상대값입니다.** 그 지자체·그 분야 안에서의 순위이므로 지역 간·분야 간 색 비교는 할 수 없습니다.

### 중점관리분야 맞춤형 사업 종합도 (2026-10-06) — `tools/overview-map/`

웹앱과 **별개의 산출물**입니다. 41개 지자체마다 "조사지 + 사업지(존) + 사업 내용" 을 한 장의
지도(SVG, 1920×1080)로 만듭니다. 남해군을 시험으로 먼저 만들었고, 컨펌 뒤 나머지를 같은 기준으로 돌립니다.

```
tools/overview-map/regions/<지역>.json   사업지 4곳의 글·좌표·동선 (사람이 적는 유일한 파일)
tools/overview-map/build-overview-map.mjs  SHP → SVG
tools/overview-map/icons.mjs               아이콘 기호 (짙은 둥근 사각 + 흰 선)
output/overview-map/<지역>/<지역>_종합도.svg  결과 (🚫 커밋 안 함 — 위성영상이 들어 있어 4~5MB)
```

| 명령 (`tools/` 안에서) | 하는 일 |
|---|---|
| `npm run overview -- namhae` | 종합도 SVG 생성 |
| `npm run overview -- namhae --grid --width=1500 --center=1050150,1634950` | **디버그** — 상자 없이 100m 격자 + EPSG:5179 좌표만 보임. 사업지 좌표·동선을 고를 때 |

**지자체마다 필요한 자료 (이것만 받으면 됩니다)** — `data/raw/SDM_5K/<코드_지역>/` 에 연속수치지형도(1:5,000) 폴더째

| 레이어 | 코드 | 쓰임 |
|---|---|---|
| 도로경계(면) | `N3A_A0010000` | 도로 |
| 건물(면) | `N3A_B0010000` | 건물 · **사업지 좌표 찾기**(도로명코드 `RDNM` + 건물번호 `BONU`, 명칭 `ANNO`) |
| 경지계(면) | `N3A_D0010000` | 전·답 |
| 하천경계·실폭하천·호수저수지(면) | `N3A_E0010001` `N3A_E0032111` `N3A_E0052114` | 수계 |
| 행정경계 시군구·읍면동(면) | `N3A_G0100000` `N3A_G0110000` | 경계선 · **바다 판정**(폴리곤 밖 = 바다) |

쓰지 않는 것: `G0010000`(시도) · `G0020000`(수부지형경계 — 해수욕장 등 작은 면) · `N3L_G0030000`(기타경계 선).
조사지는 `data/raw/gis_0901/최종 조사지/<지역>_OverlapUnion_1.shp`, 바탕은 **브이월드 위성 타일**(인증키 불필요, `data/raw/tiles/` 캐시).

**그리는 순서** — 위성(채도 0.28·밝기↑) → 바다 덮기(읍면 폴리곤 밖) → 전답 → 수계 → 도로 → 건물 → 해안선/읍면 경계 →
**조사지 밖 어둡게**(`dim` 0.24) · 안 밝게 → 동선 → 지명 → 지시선 → 설명 상자 → 제목·범례·축척.
- 읍면 폴리곤 변 중 **두 읍면이 함께 쓰는 변만 행정경계(점선)**, 나머지는 해안선(가는 실선). 통째로 점선을 치면 해안선이 행정경계로 보입니다.
- 좌표는 SHP(5179)·조사지(5186) 모두 WGS84 → **웹 메르카토르 타일 픽셀**로 바꿉니다. 위성 타일을 비틀지 않기 위해서입니다.
- 폰트는 Pretendard → Noto Sans KR → 맑은 고딕 순으로 떨어집니다. SVG 를 여는 쪽 컴퓨터에 글꼴이 있어야 같은 모양입니다.

**남해 사업지 좌표를 찾은 방법** — 건물 레이어의 도로명코드 `3343017`(미조로)로 236·168 번지 건물을, `ANNO` 로 미조면보건지소를 찾았습니다.
망산·미송로2번길·미조남항은 지도에서 보고 남항 서측 안벽에 찍었습니다(확인 필요). 디버그 격자로 좌표를 읽어 JSON 에 적는 방식입니다.

**★ 대상지 경계·히트맵은 우리가 규칙으로 재현 (2026-10-06, AURI 정호경 연구원 답변 → 담당자 결정)** — `tools/overview-map/risk.mjs`

AURI 답변: 사전진단서의 좁은 경계는 **산식 없이** 중점 3분야 TIF 가 겹치는 곳을 눈으로 잡은 것이고, 종합 위험도 이미지는
7개 TIF 를 **분야별 색 + 값에 따른 투명도**로 겹친 시각화(가중치·합산 없음)입니다. 눈으로 한 것을 41곳에 같은 기준으로
돌리기 위해 아래 규칙으로 바꿨습니다. 숫자는 `regions/<지역>.json` 의 `risk` 항목(또는 `--overlapT=0.2` 같은 명령줄)에서 바꿉니다.

| | 규칙 | 기본값 |
|---|---|---|
| 히트맵 | 중점 3분야 TIF(`data/raw/gis_0901/density/`) · t = 값 ÷ 지자체 p99 · 흰→분야색(t^0.75) · 투명도 min(1, t/0.6)×0.5 · 차례로 겹침 | AURI 7색: 산재 빨강·감염병 주황·교통 노랑·범죄 초록·자살 파랑·화재 남색·생활안전 보라 |
| 대상지 ① | 세 분야 **모두** t ≥ `overlapT` 인 10m 칸 = 3분야 중첩 구간 | 0.20 |
| 대상지 ② | 건물·도로(SHP)에서 `builtBufferM` 안 = 시가지 (산지 제외) | 40m |
| 대상지 ③ | ①∧② → `closeM` 닫기 → `minAreaHa` 미만 조각 버림 → 구멍 메움 → 테두리 다각형(`simplifyM`) | 30m · 1ha · 12m |

- 남해: 중첩 칸 2,231 → 시가지 교집합 1,789 → **18.2ha 한 덩어리**(미조항 북측 시가지). 공식 조사지 61.3ha 는 흰 점선 참고선으로 남김.
  `overlapT` 0.30 → 14.7ha · 0.12 → 21.1ha. 어느 값이든 남항 서측·동측 해안도로(사업지 03·04)는 3분야 중첩 밖입니다.
- 결과 경계는 `output/overview-map/<지역>/<지역>_대상지.geojson`(WGS84, 규칙값 포함)으로도 저장됩니다.
- 히트맵은 조사지 밖까지 그려지고 `dim` 이 그 위를 덮습니다. 웹앱에는 반영하지 않습니다(담당자 결정 2026-10-06).
