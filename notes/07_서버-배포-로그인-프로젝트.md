### 계정 로그인 (2026-09-14) — `server/auth.js`

8/25 협의의 **"승인제 회원가입 + 로그인 기반 접근통제"** 입니다.

```
가입 신청(아이디·비밀번호·이름·소속) → pending → 관리자 승인 → active → 로그인
                                        └ 거부 → rejected   └ 비활성화 → disabled (즉시 로그아웃)
```

**방식 스위치 — `AUTH_MODE`** (문제가 생기면 이 한 줄로 되돌립니다)

| 값 | 무엇 | 언제 |
|---|---|---|
| `account` | 계정 로그인 (**기본값**) | 렌더 |
| `code` | 예전 `ACCESS_CODE` 방식 — 코드를 지우지 않고 남겨 둠 | **되돌리기** |
| `off` | 확인 안 함 | 내 컴퓨터 개발용만 |

⚠️ `account` 인데 DB 에 못 붙으면 **사이트를 닫습니다**(503 "설정 필요" 화면). 열어 두면 로그인 없이 누구나
들어오기 때문입니다. DB 가 늦게 깨어나면 30초마다 다시 붙어 보고, 붙는 순간 저절로 열립니다.

**서버가 문을 지킵니다** — 브라우저 쪽에서만 막으면 주소를 직접 쳐서 들어올 수 있기 때문입니다.

| 로그인 전에도 받을 수 있는 것 | 로그인 뒤에만 |
|---|---|
| `login.html` · `assets/` 의 css·js·svg·png·jpg | 나머지 모든 `.html` · `data/` · `assets/*.json` · 모든 `/api/` |

- 로그인 안 한 채 화면을 열면 `login.html?next=…` 로 보내고, 로그인하면 원래 화면으로 돌아옵니다
- `admin.html` 과 `/api/admin/*` 은 **관리자만**. 일반 사용자는 첫 화면으로 돌려보냄
- 화면(HTML)에는 `Cache-Control: no-store` — 로그아웃 뒤 "뒤로 가기"로 다시 보이지 않게

**비밀번호** — bcrypt 해시만 저장 (`bcryptjs`, 비용 12). 원문은 DB·로그·화면 어디에도 없습니다.
`bcryptjs` 는 bcrypt 알고리즘의 순수 자바스크립트 구현이라 해시 형식(`$2b$12$…`)이 같고 컴파일 없이 설치됩니다.

**세션 — 마지막 활동 후 30분** (`SESSION_MINUTES`)

| | 만료가 30분 뒤로 밀리나 |
|---|---|
| 화면 열기 · AI 기능 사용 · **로그인 유지** 버튼 | ✅ |
| 화면이 1분마다 남은 시간 확인(`/api/auth/me`) · 자료(.json) 받기 | ❌ — 창만 열어 두면 끝나야 하므로 |

- 상단 바 위 **계정 줄**에 이름·아이디·소속, 남은 시간, 로그인 유지, (관리자면) 계정 관리, 로그아웃
- **5분 남으면** 계정 줄이 경고로 바뀌어 "로그인 유지"를 누르라고 안내 — 요청의 "로그인 유지 확인 기능"을 이렇게 해석했습니다

**틀리지 않게 한 것**
- 로그인은 **비밀번호를 먼저** 확인하고, 맞을 때만 "승인 대기 중입니다" 를 알려 줍니다. 순서가 거꾸로면 비밀번호 없이 가입 여부를 알아낼 수 있습니다. 없는 아이디·틀린 비밀번호는 같은 문구, 같은 응답 시간
- 같은 IP 에서 **10번 틀리면 15분 차단**
- 관리자 계정은 **화면에서 끌 수 없습니다** (실수로 모두 잠기는 것 방지). `ADMIN_ID`·`ADMIN_PW` 환경변수로만 — 서버가 켜질 때 없으면 만들고, **있으면 비밀번호를 환경변수 값으로 다시 맞춥니다**(잊으면 환경변수만 바꾸면 됨)
- 비활성화하면 이미 열린 세션도 **즉시** 끊습니다
- 접속자 IP 는 Cloudflare 가 덮어쓰는 `CF-Connecting-IP`·`True-Client-IP` 를 먼저 씁니다 (`X-Forwarded-For` 첫 칸은 접속자가 꾸며 보낼 수 있음). 요금 상한도 같은 함수

**저장 창**
- 이름(비우면 지자체 이름) · 내 프로젝트를 연 탭이면 **덮어쓰기 / 새로 저장** 선택
- 프로젝트를 연 뒤 **진단 위치가 바뀌었으면 "새로 저장"이 먼저 골라집니다** — 다른 지점의 진단으로 예전 프로젝트를 덮어쓰는 실수 방지
- 현장 사진이 있으면 "함께 저장" 체크(기본 켬) + **사람·차량번호가 서버에 저장된다**는 안내
- 저장 크기 표시. 한 건 **25MB** 한도

**열기**
- 지금 탭에 다른 진단이 있으면 확인을 묻고, **10칸을 모두 비운 뒤** 채웁니다(앞 진단의 개선 후 이미지가 섞여 남지 않게)
- 판독 결과가 있으면 **리포트(3단계)**, 위치만 있으면 진단(2단계)으로 갑니다
- 브라우저 저장 공간(보통 5MB)을 넘으면 반쯤 채운 상태를 남기지 않고 다시 비운 뒤 안내합니다

⚠️ **DB 용량** — 이미지가 들어 있어 한 건이 수백 KB ~ 수 MB 입니다. 렌더 무료 DB(1GB)면 **대략 수백 건**이 한도입니다. 목록에 건별 크기가 나옵니다. 30일 만료와 함께 유료 전환을 검토할 이유가 하나 더 생겼습니다.

**시험** — 메모리 PostgreSQL 로 서버 31건(저장·목록·열기·덮어쓰기·관리자 열람·삭제·비활성 사용자) + `assets/projects.js` 를 가짜 브라우저 저장소로 돌려 11건(찌꺼기 제거·취소·공간 초과·열린 프로젝트 삭제). 기존 로그인 시험 52건 영향 없음. 저장 창 화면 자체는 브라우저로 못 봤습니다.

### 사진 누적 구조 — 제안 (2026-09-07 AURI 요청, 아직 만들지 않음)

> "사전 진단을 계속하면 할수록 현장 기록이 쌓여서, 이 지역 문제가 해소됐는지
>  판단 가능한 툴로 진화"

지금 사진은 `sessionStorage` 에 있습니다. **탭을 닫으면 사라집니다** — 누적이 될 수 없습니다.
누적하려면 저장 위치가 서버여야 하고, 그러면 아래가 함께 결정돼야 합니다.

| 정해야 할 것 | 왜 |
|---|---|
| **어디에 저장하나** | 배포처(Render)는 디스크가 껐다 켜면 지워집니다. 별도 저장소가 필요 |
| **개인정보** | 현장 사진에는 사람·차량번호가 찍힙니다. `data/raw/` 와 같은 등급의 자료가 됩니다 |
| **누가 볼 수 있나** | 지금 서버는 암호가 없습니다(`ACCESS_CODE` 미설정). 사진을 쌓으면 접근통제가 먼저입니다 |

만든다면 이런 모양입니다 (좌표를 열쇠로 삼는 것이 핵심).

```
POST /api/site-photos   { lat, lng, dataUrl, takenAt, note }
GET  /api/site-photos?lat=&lng=&radius=100   → 촬영시각 오름차순
```

- **같은 지점 판정은 좌표 반올림**으로 합니다 (격자와 같은 50m). GPS 오차가 있어
  "정확히 같은 좌표"로는 절대 안 묶입니다.
- 촬영시각은 이미 EXIF 에서 읽고 있습니다(`site-photo.js`) — 정렬 열쇠가 이미 있습니다.
- 화면은 4장 사진 자리에 **"이 지점 이전 기록 3건"** 을 띄우고 시간순으로 늘어놓으면 됩니다.

정한 뒤에 붙이는 편이 안전합니다. 개인정보가 실린 사진을 암호 없는 서버에 쌓기 시작하면
