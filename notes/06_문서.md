### 문서 2종으로 분리 (2026-09-07 AURI 화상회의)

5단계 `document.html` 이 **탭 두 개**로 나뉩니다. 하나였을 때는 AURI 양식에 없는
칸이 섞여 들어가 "이게 사전진단서인지 우리 리포트인지" 알 수 없었습니다.

| 탭 | 무엇 | 누가 읽는가 |
|---|---|---|
| **현장용 리포트** (첫 탭) | 진단 위치 · 현장 확인사항 · 개선 전/후 · 사업 목록 | 현장 나가는 실무자 |
| **사전진단서** | AURI 양식 그대로 — 표지 · 1~5장 | AURI·행안부 제출용 |

- ★ **순서 — 현장용 리포트 → 사전진단서** (2026-09-14 AURI 회의). *"현장에 나가기 전 예비 확인을
  먼저 하고, 사전진단서가 그다음 결과로 나오는 순서가 맞다."* 탭 순서와 처음 열리는 탭이 모두
  현장용 리포트입니다. 안쪽 이름(`docA`=사전진단서, `docB`=현장용)은 그대로 두고 보이는 순서만 바꿨습니다.

- **사전진단서에는 AURI 원문에 없는 요소를 넣지 않습니다.** 우리가 계산한 종합 위험지수,
  적합도 점수, 규칙 번호 같은 것은 현장용 리포트로 갑니다.
- **AURI 숫자는 계속 바뀝니다.** 그래서 맞춰야 하는 것은 값이 아니라 **구조와 서식**입니다.
- 각각 따로 인쇄됩니다 — 인쇄할 때 보이지 않는 탭은 통째로 감춥니다.

### 문서 빈칸 — 편집칸 + AI 초안 (`assets/doc-edit.js` · `/api/opinion`)

전에는 "여기는 사람이 채우는 자리입니다"라는 **고정 안내문**이었습니다. 웹에서 고칠 수도
없고 인쇄하면 그 안내문이 보고서에 그대로 실렸습니다. 이제 **빈 입력칸**입니다.

- 안내문은 placeholder 로 들어가 **화면에만** 보입니다.
- **AI 초안 버튼**을 눌렀을 때만 글이 생깁니다. 평소에는 비어 있습니다.
- 사람이 **한 글자라도 고치면 AI 표시가 사라집니다** — 그때부터는 사람이 쓴 글입니다.
- AI 표시는 **화면에만** 보이고 인쇄에는 안 나옵니다. 최종 문서에 "AI가 썼다"고 적히면
  행정 문서로 쓰기 어렵고, 어차피 사람이 검토해 확정한 글이기 때문입니다.
- 저장은 `auri_doc_notes`.

**인쇄는 입력칸이 아니라 사본을 찍습니다** (2026-09-07)

입력칸(textarea)을 그대로 인쇄하면 **글이 길 때 칸 안에서 잘리고**, 서체·크기가
본문과 달라 이질적으로 보입니다. 그래서 같은 글을 담은 `.doc-fill-print` 사본을
옆에 두고, 인쇄할 때 입력칸을 감추고 사본을 보입니다. 사본은 그냥 글이라 잘릴 일이
없고 본문 서식을 그대로 받습니다.

| | 화면 | 인쇄 |
|---|---|---|
| 입력칸 | 보임 | 감춤 (사본으로 대체) |
| AI 초안 표시 | 보임 | **감춤** — 행정 문서에 "AI가 썼다"고 적히면 안 됨 |
| **판단 근거** | 보임 | **보임** — 무엇에 기대어 쓴 글인지 종이에 남아야 함 |
| 대조 전 근거 안내 | 보임 | 감춤 — 우리 시스템 상태이지 문서의 근거가 아님 |

화면에서는 글 길이에 맞춰 칸 높이가 늘어납니다(`autoGrow`). 감춰진 탭에서는
높이를 잴 수 없어 건너뛰고, 탭을 열 때 다시 맞춥니다.

**★ 법령을 지어내지 못하게 막는 방법 (`server/legal.js`)**

AI에게 "관련 법령을 근거로 들어라"고만 하면 없는 조항을 지어냅니다. 그러면 행정 문서로
쓸 수 없습니다. 그래서 **조문 원문을 프롬프트에 미리 넣고, 그 안에서만 인용하게** 합니다.

```
server/legal.js  →  legalBlock()  →  프롬프트에 붙임  →  AI는 이 목록 밖을 인용 못 함
```

- 근거를 못 찾으면 **"관련 근거 확인 필요"** 로 두게 지시합니다. 억지로 붙이는 것보다 낫습니다.
- 조문을 늘리려면 `LEGAL_BASIS` 배열에 한 덩어리 추가하면 됩니다. **원문을 그대로** 넣으세요.

**★ 대조를 마친 것(`verified: true`)만 지시문에 들어갑니다** (2026-09-07)

대조 전인 것을 넣고 화면에 경고만 띄우면 실무자가 그대로 인용해 행정 문서에 실립니다.
그래서 **AI에게 아예 보여 주지 않습니다.**

| | |
|---|---|
| `legalBlock()` | `verified: true` 만 지시문에 넣음. 하나도 없으면 "법령을 언급하지 말라"고 지시 |
| `PENDING` | 대조 전이라 **쓰지 않은** 근거. 화면에만 "인용하지 않았음"으로 표시 |

**★ 근거는 세 유형이고 인용 방식이 다릅니다** (`kind` · `BASIS_KINDS`)

성격이 다른 것을 같은 형식으로 인용하면 문서가 틀린 말을 합니다.
특히 국정과제를 "○○법 제△조에 따라"로 쓰면 안 됩니다.

| `kind` | 표기 | 무엇 | 인용 범위 |
|---|---|---|---|
| `law` | **법령** | 법률 조문 | **조문 번호와 제목까지만.** 본문 전문은 인용하지 않음 |
| `policy` | **정책** | 국정과제 등 | "…에 따른 사업 방향" 꼴. 법령 형식 금지 |
| `consult` | **협의** | 회의록·검토 의견 | 요지를 풀어 써도 됨 |

**본문 전문을 인용하지 않는 이유**: 조문은 개정으로 자구가 바뀝니다. 우리가 옮겨 적은 문구가
현행과 한 글자라도 다르면 그대로 오류가 됩니다. 조문 번호와 제목은 안정적이고, 그것만으로
근거 제시가 됩니다. 그래서 `gist`(요지)는 **사람이 읽는 메모**일 뿐 지시문에 넣지 않습니다 —
협의 문서만 예외입니다(원문이 우리 손에 있어 요지를 책임질 수 있음).

각 항목의 `cite` 문구를 **글자 그대로** 쓰게 합니다.

| ID | 유형 | 인용 문구 | 상태 |
|---|---|---|---|
| `DSMA-66-13` | 법령 | 재난 및 안전관리 기본법 제66조의13(안전사업지구의 지정 및 지원, **2025.10.1. 시행 기준**) | ✅ 조문 번호·제목 확인 |
| `DSMA-PURPOSE` | 법령 | 재난 및 안전관리 기본법 제1조(목적) | ✅ 조문 번호 확인 |
| `POLICY-72-73` | 정책 | 국정과제 72·73(지역안전지수 고도화 및 안전취약지역 관리) | ⏸ **원문 확인 중** |
| `MOIS-2026-08-25` | 협의 | 행정안전부 협의(2026-08-25) 「개선사업 재정리 방향」 | ✅ 회의록 원문 확인 |
| `MOIS-REPORT-FORM` | 협의 | 행정안전부 「데이터 분석 결과 보고서」 보완사항 검토 | ✅ 원문 PDF 확인 |
| `ORDINANCE-LOCAL` | 조례 | 해당 지자체 재난안전 관련 조례 | ⏸ **지자체별 확인 필요** |

**★ 조례는 네 번째 유형(`ordinance`)으로 넣되 인용하지 않습니다** (2026-09-07 AURI 요청)

AURI 가 "해당 지자체 재난안전 관련 조례(예: 부천시)"를 근거로 넣자고 요청했습니다.
다만 조례는 **41개 지자체가 각각 다르고** 이름·조 번호·현행 여부를 하나도 확인하지
못했습니다. 확인 안 된 조례를 AI 에게 보여 주면 "부천시 안전도시 조성 조례 제5조" 같은
그럴듯한 문장을 만들어 냅니다.

| | |
|---|---|
| 지금 | `verified: false` → **지시문에서 제외**. 화면에만 "인용하지 않은 근거"로 표시 |
| AI 지시문 | 조례가 필요해 보이면 본문에 쓰지 말고 `확인필요` 로 적으라고 명시 |
| 나중에 | 지자체별로 확인해 `ORDINANCE_BY_REGION` 에 넣고 `verified: true` 로 |

→ 결과적으로 지금 AI 가 인용할 수 있는 것은 **법령 2건 + 협의 2건**뿐입니다.

**⚠️ 제66조의13 은 최근 개정으로 이동한 조항입니다.** 시점을 반드시 함께 적습니다 —
개정 전 자료를 본 사람은 **제66조의12** 로 알고 있습니다.

| | |
|---|---|
| 2022년 기준 | 제66조의12 (안전사업지구의 지정 및 지원) |
| 법률 제20653호 개정 | 종전 66조의13·14 가 각각 14·15 로 밀림 |
| **2025.10.1. 시행** (법률 제21065호) | **제66조의13** ← 현행 |

⚠️ 두 법령 모두 **조문 본문 전문은 아직 대조하지 않았습니다.** 번호와 제목만 확인된
상태라 본문 인용을 막아 둔 것이며, 이 상태로도 근거 제시는 됩니다.

### 현장 사진 업로드 (`assets/site-photo.js`)

사전진단서 4장은 **왼쪽 지도 · 오른쪽 사진**입니다. 여러 장 올릴 수 있습니다.

- **EXIF에서 GPS 좌표와 촬영시각을 읽어** 지도에 자동으로 찍습니다.
- ⚠️ **카카오톡으로 주고받은 사진은 EXIF가 지워집니다.** 그럴 때는
  "지도에서 위치를 지정해 주세요"로 안내하고, 지정한 좌표를 붙입니다(캡션에 `(지도에서 지정)` 표시).
- **사진을 서버로 보내지 않습니다.** 위치와 사람이 찍히므로 보낼 이유가 없으면 안 보냅니다.
  ⚠️ **예외 (2026-09-15)** — **프로젝트 저장**에서 "현장 사진 함께 저장"을 켜면(기본 켜짐) 사진이 서버 DB 에 저장됩니다. 저장 창에 그 사실을 적어 두었고, 끄면 사진만 빼고 저장합니다.
  EXIF 읽기도 브라우저 안에서 합니다(라이브러리 없이 APP1 구역만 훑음).
- 긴 변 1400px로 줄여 담습니다 — 원본 그대로면 sessionStorage 한도를 넘습니다.
- **어느 절에 실을지 고릅니다** (`field`). 여러 장을 올리면 사진이 가장 적은 절부터
  하나씩 자동 배정되고(세 장이면 4.1·4.2·4.3), 드롭다운으로 바꿀 수 있습니다.
  한 절에 두 장 이상이면 첫 장이 크게, 나머지는 아래에 작게 붙습니다.
- 좌표가 없는 사진은 **지도에서 지정** 버튼으로 찍습니다. 아래 지도와 같은 방식이라
  누른 자리를 그대로 위경도로 되돌립니다.

### 문서에 싣는 지도 (`assets/doc-map.js`) — 2026-09-07

사전진단서 3.1(중점대상지 종합위험도)과 4장(밀집구간별)에 지도가 들어갑니다.
**지도 화면을 캡처하는 것이 아니라 캔버스에 직접 그려 그림으로 넣습니다.**

**★ 왜 네이버 지도를 캡처하지 않는가**

캡처할 수 없기 때문입니다. 타일이 다른 서버(pstatic.net)에서 오는데 그 서버가
"가져다 써도 된다"는 표시(CORS)를 붙여 주지 않아 **캔버스가 오염되어 저장이 막힙니다.**
스트리트뷰 캡처가 막힌 것과 같은 이유입니다(7절). **html2canvas 를 써도 같은 곳에서
막힙니다** — 그 도구도 결국 같은 캔버스에 그려 넣기 때문입니다.

**그래서 브이월드입니다** (국토교통부 공공 서비스, 2026-09-07 확인)

```
https://xdworld.vworld.kr/2d/Base/service/{z}/{x}/{y}.png
→ Access-Control-Allow-Origin: *   ★ 이것 때문에 됩니다
→ 인증키 불필요 · 256×256 PNG
```

폐쇄망으로 갈 때도 이쪽이 낫습니다. 필요한 구간의 타일만 미리 받아 두면 되고,
공공 자료라 반출 문제가 없습니다.

| | |
|---|---|
| 3.1 | 1000×620 · 조사지 경계(붉은 점선) + 7개 분야 출동 지점 + 진단 지점 |
| 4.x | 760×570 · 진단 지점 반경 **450m**(`MAP_RADIUS_M`) + 그 분야 지점만 |
| 분야 색 | `MAP_COLORS` — `index.html` 의 `INCIDENT_CATEGORIES` 와 **같은 값** |
| 함께 그림 | 축척 막대 · 출처 문구 |

- **배경 없이도 됩니다.** `base: false` 를 넘기면 타일을 받지 않고 경계선과 점만
  그립니다. 망이 끊겨도, 타일을 못 받아도 지도가 나옵니다(타일 한 장이 실패해도
  그 자리만 비고 나머지는 그려집니다).
- 확대 단계는 범위에 맞춰 자동으로 고릅니다(`fitZoom`). 여백 비율(`pad`)이 크면
  한 단계 멀어져 거리가 안 보이므로 4장은 5%로 좁혀 두었습니다.
- 한 번 그린 지도는 `_mapCache` 에 남아 다시 그리지 않습니다. 사진을 올려 문서를
  다시 그려도 타일을 또 받지 않습니다.
- 문서를 먼저 띄우고 지도는 **뒤따라 채웁니다** — 타일을 기다리느라 문서가 늦게
  뜨면 안 되기 때문입니다.

### HEA 색 구분 (`assets/theme.css`)

세 유형이 서로 구분되게 각각 다른 색을 줍니다. 진단서 부록은 **행 배경을 아주 옅게** 깔았습니다.

| | 글자색 | 부록 행 배경 |
|---|---|---|
| **[E]** 환경 개선 | `--g3` (짙은 회색) | `rgba(102,102,102,.045)` |
| **[A]** 행위 개입 | `--contrast` (파랑) | `rgba(39,147,201,.055)` |
| **[H]** 피해대상 보호·지원 | `--main` (메인) | `rgba(216,61,100,.05)` |

- 배경은 **거의 안 보일 만큼 옅게** 둡니다. 카드·박스를 쓰지 않는 디자인 규칙과 부딪치지 않게,
  칠하는 것이 아니라 "줄이 어렴풋이 묶여 보이는" 정도입니다.
