### 진단 → 처방 연결 (항목별 판독) ★ 이 앱의 핵심

**시설물을 고르는 것은 분야 점수가 아니라 "사진에서 문제로 확인된 체크리스트 항목"입니다.**

```
사진 → 항목마다 예/아니오/확인불가 → 문제 항목이 시설물을 부름 → 처방
        (CRM-1 가로등 있는가 = 아니오)   (LED 보안등 · CPTED 조명)
```

- 같은 점수라도 **사진이 다르면 처방이 다릅니다.** 범죄 80점이어도 "가로등 없음"과 "CCTV 없음"은 전혀 다른 시설물이 나옵니다.
- 여러 항목이 같은 시설물을 불러도 **한 번만** 들어갑니다.

**개수는 판정이 정합니다** (`RX_MAX_BY_LEVEL`)

| 판정 | 처방 개수 |
|---|---|
| 위험 (67~100) | **2종** |
| 주의 (34~66) | **1종** |
| 안전 (0~33) | 0종 |

예) 7개 분야가 위험 2 · 주의 4 · 안전 1 → `2×2 + 4×1` = **8종**. 사진에서 문제가 아무리 많이 잡혀도 개수는 이 규칙을 넘지 않습니다.

**어느 것을 뽑을지는 적합도(0~100)가 정합니다** (`auriFitScore`)

"이 사진에 이 시설물이 얼마나 들어맞는가"를 AI의 항목별 판독에서 **규칙으로 계산**합니다. AI에게 시설물 점수를 직접 묻지 않는 것은, 처방 근거가 되짚어지지 않으면 감사 추적이 깨지기 때문입니다.

1. **분야 점수가 높을수록** — 문제가 심한 곳일수록 잘 들어맞음
2. **그 문제의 1순위 대책일수록** — `byItem` 배열의 앞자리. 뒷자리는 같은 문제를 푸는 **대안**이므로 적합도가 절반으로 떨어집니다 (`점수 ÷ (순위+1)`)
3. **여러 항목에서 함께 확인될수록** — 근거가 겹치면 항목당 +8점 (최대 +15)

분야 안에서 이 점수로 줄을 세워 **상위 N개**만 뽑습니다. 점수가 같으면 규칙표에 적힌 순서를 따릅니다.

**필수/권장도 적합도로 갈립니다** — `RX_MUST_FIT`(67) 이상이면 필수. 위험/주의를 가르는 경계와 같은 값이라, 보통 위험 분야의 1순위는 필수, 그 분야의 2순위(대안)나 주의 분야는 권장이 됩니다.

근거 줄에 적합도가 함께 찍혀서 **왜 이것이 뽑혔고 왜 필수인지**를 되짚을 수 있습니다.
- 처방 근거 줄에 **어느 항목이 이 시설물을 불렀는지**가 찍힙니다:
  `근거: 사진 판독 CRM-1 — 가로등 미설치 → 규칙 R-CRM-01 · 범죄 위험 판정 · 표준단가 95만원/개소`

**세 파일이 번호로 맞물립니다. 하나만 고치면 조용히 끊깁니다.**

| 파일 | 무엇을 정하는가 |
|---|---|
| `server/checklist.js` | 항목 번호(`CRM-1`) · 질문 · **어느 답이 문제인가**(`risk: 'yes'\|'no'`) |
| `server/server.js` | AI가 항목마다 답하도록 강제, 답에 "문제 있음" 표시를 붙여 전달 |
| `assets/rules.js` | `byItem` — 항목 번호 → 시설물 |

- 체크리스트에 항목을 추가하면 `rules.js`의 `byItem`에도 그 번호를 넣어야 처방에 반영됩니다. 안 넣으면 **점수에만** 반영됩니다.
- `risk` 폴라리티 때문에 **질문은 반드시 예/아니오로 답할 수 있어야** 합니다. ("관리 상태가 어떠한가" 같은 문장 금지)
- 점검: `node tools/verify-rules.mjs` (또는 `npm run verify-rules --prefix tools`) — 세 파일의 번호·이름·단가·개입 유형이 어긋나지 않는지 확인합니다 (항목 양방향 일치, 62종 전부 단가·유형 보유). checklist.js나 rules.js를 고칠 때마다 돌려 보세요.

**도구 명령 정리** (`tools/` 폴더에서)
| 명령 | 하는 일 | 언제 |

**`fallback` — 항목 판독이 없을 때만** 쓰는 예비 목록입니다. 서버가 꺼져 더미 점수로 돌 때, 예전 세션 데이터를 열었을 때 예전 방식(분야 단위)으로 처방합니다. 지우지 마세요.

⚠️ **연구원이 판독 근거 글(`observed`)을 고쳐도 처방은 바뀌지 않습니다.** 처방을 바꾸려면 **재판독(`/api/revise`)** 을 쓰세요 — 그쪽은 항목 답까지 다시 받습니다.

⚠️ AI가 분야당 요약 하나가 아니라 **항목 43개에 각각 답하므로** 출력 토큰과 호출 시간이 늘어납니다.

### AI 진단 구조 (2단계)

```
브라우저(diagnosis.html)  →  중계 서버(server/)  →  AI
                                ↑ API 키는 여기에만 보관
```

- **`server/checklist.js`** — 7대 분야별 "사진에서 무엇을 볼 것인가" 목록. **이 프로젝트에서 가장 중요한 파일**이며, 담당자가 계속 고쳐 나갑니다. 이 파일을 고치면 진단 기준이 바뀝니다.
- **`server/server.js`** — 화면 파일을 띄워 주고, 사진을 AI에 넘겨 점수표를 받습니다.
- AI는 점수뿐 아니라 **판독 근거(`observed`)와 확인 불가 항목(`notVisible`)**을 함께 돌려줍니다. "사진 → 판독 → 점수 → 시설물 → 예산"을 역추적하기 위한 것입니다.
- 출력 형식(JSON)은 스키마로 강제하므로 형식이 어긋날 수 없습니다.
- **폐쇄망 전환**: `server.js`의 `callAI()` 함수 안쪽만 로컬 sLLM 호출로 바꾸면 됩니다. **화면(HTML)은 수정 불필요.**

### 재판독 — AI 오독을 사람이 바로잡는 장치 (`/api/revise`)

AI는 사진을 잘못 읽습니다. 실제로 확인된 사례:
- 철제 **현관문**을 외부 **계단**으로 판독 → 자살 위험 점수 과대
- 노면의 `일방통행·거주자 우선주차`를 `어린이 보호구역`으로 판독

그래서 진단 결과 아래에 **"결과에 오류가 있나요?"** 칸을 두었습니다. 연구원이 잘못 본 부분을 적어 보내면 AI가 다시 판독합니다.

- **연구원의 지적이 AI의 이전 판독보다 우선**합니다 (`buildRevisePrompt`). AI가 자기 판단을 고집하면 이 기능이 무의미해지므로 지시문에 명시돼 있습니다.
- 잘못 본 대상을 근거로 매겼던 **점수까지 다시 계산**합니다.
- 지적과 무관한 분야는 건드리지 않습니다.
- 지적 내용은 `auri_revision_log`에 남아 **진단서 서식1의 "판독 보정 이력"에 인용**됩니다.

### 사업 팔레트 (`assets/palette.json`) — AURI 자료

**임의로 만들었던 시설물 62종을 AURI 팔레트 289종으로 교체했습니다** (2026-09-04).
원본: `7대유형_통합_HEA_성과증명_사업팔레트_0902.xlsx`

```
assets/palette.json   어떤 사업이 있는가   ← AURI 자료. 자동 생성, 손대지 않음
assets/rules.js       언제 그 사업인가     ← 우리 판단 (연결표)
```

**나눠 둔 이유**: 팔레트가 아직 확정본이 아닙니다. 새 엑셀을 받으면
`npm run palette --prefix tools` 만 돌리면 되고, 사업명이 바뀌어 연결이
끊어진 곳은 `npm run verify-rules --prefix tools` 가 잡아 줍니다.

| | |
|---|---|
| 사업 수 | 289종 (교통 46 · 화재 44 · 자살 44 · 감염병 44 · 범죄 38 · 생활안전 38 · 산재 35) |
| HEA | E 119 · A 105 · H 65 |
| 효과크기 채움률 | **98%** / 출처 **95%** |
| 연결표가 실제로 쓰는 것 | 83종 (나머지는 연구원이 드롭다운에서 고를 수 있는 범위) |

**엑셀 읽는 규칙**
- 시트마다 표가 **두 덩어리** 쌓여 있고 위쪽만 셀에 배경색이 있습니다.
  **칠해진 쪽(위) = 기존 팔레트 · 안 칠해진 쪽(아래) = 신규 팔레트.** 같은 사업명은 신규를 남깁니다(145건 정리).
  - 근거는 AURI 우제헌 연구원 메일: *"색이 있는 부분은 기존 사업팔레트이며, 그 아래 색이 없는 부분은 비중을 차등화하여 새롭게 정리한 팔레트입니다."*
  - 신규 팔레트는 HEA를 다시 매긴 것이 확인됩니다 — 단속·점검이 E→A로(불법주정차 무인단속, 어린이 놀이시설 안전점검), 지원사업이 E→H로(주택용 소방시설 지원, 취약 어르신 낙상방지 안심홈) 옮겨졌습니다. "비중 차등화"가 이것입니다.
  - 뒤집어야 하면 `build-palette.mjs`의 `COLORED_IS_NEW` 한 줄만 바꾸면 됩니다.
- 산업재해 시트는 `구분` 열이 하나 더 있어 **머리글 이름으로** 열을 찾습니다.
- HEA 칸에도 색이 칠해져 있지만 A가 5가지 색으로 나와 **일관성이 없어 무시**합니다. 글자(H/E/A)만 씁니다.
- 요약 시트는 해설이라 건너뜁니다. (요약의 596건은 정리 전 모음집 기준이라 상세 시트 합계와 다릅니다)

**HEA = 8/25 협의의 3분류**

| | | 이미지 |
|---|---|---|
| **H** 피해대상 보호·지원 | 검진·접종·용품 지원·상담 | 그릴 수 없음 |
| **E** 환경적 개입 | 시설 설치·정비 | **그림** |
| **A** 행위 개입 | 단속·교육·홍보·제도 | 그릴 수 없음 |

- **개선 후 이미지에는 E만 들어갑니다.** 나머지는 거리 사진에 나타나지 않아 넣으면 모델이 없는 시설을 지어냅니다. 목록·예산·문서에는 그대로 남고, 화면에 왜 빠졌는지 적힙니다.
- **자살은 E만으로 채우지 않습니다** (`RX_REQUIRE_HEA`). H 또는 A가 최소 1개 들어가며, 근거 줄에 `사람 중심 개입 필수 포함(2026-08-25 협의)`이 찍힙니다. 처방이 1종뿐인 '주의'에는 적용하지 않습니다 — 그 자리를 바꾸면 물리적 대책이 통째로 빠집니다.

**⚠️ 연결이 약한 항목 4개** (`RX_WEAK`) — 팔레트에 그 문제를 직접 다루는 사업이 아직 없습니다. AURI가 생활안전·감염병의 H·A를 재정리할 때 채울 자리입니다.

| 항목 | 무엇이 없는가 |
|---|---|
| `INF-3` | 옥외 손 위생 시설(세면대·손소독제) |
| `INF-5` | 보행로 폭·밀접 접촉 |
| `LIF-6` | 보행자와 자전거·이륜차 동선 분리 |
| `SUI-3` | 고지대·경사지 추락방지 (교량 기준만 있음) |

### 금액 — ⚠️ 팔레트에 20%만 적혀 있습니다

**우리가 단가표를 만들지 않습니다.** 금액은 AURI 팔레트의 `금액` 칸에 적힌 문구가 전부이고, 그중 **단위와 금액이 분명한 것만** 계산에 씁니다.

| | 종수 | 어떻게 표시되나 |
|---|---|---|
| 단가로 쓸 수 있음 | **15종** | 금액 계산 · 합계에 포함 |
| 금액 문구는 있으나 단가 아님 | 50종 | `산출 근거 필요 — 참고: <원문>` · 합계 제외 |
| 금액 없음 | 224종 | `산출 근거 필요` · 합계 제외 |

**왜 대부분 못 쓰는가** — 문구의 기준이 제각각이라 일괄로 숫자를 뽑으면 문서가 거짓말을 합니다.

- `개소당 2,500만원` → 씁니다 (단위 + 단일 금액)
- `안산시 노후관로 1,386km 대상 2,229억` → 그 지자체 총액. 격자 단가가 아님
- `1개소당 5~10억 이내` → 범위. 어느 쪽인지 사람이 정해야 함
- `삼척시 기준 국비 30억원 + 지방비 20억원` → 분담 방식이 문서마다 다름

제외 사유는 `amount.reason`에 남고, 서식2 아래에 참고 문구를 모아 보여 줍니다. 판정 규칙은 `tools/build-palette.mjs`의 `readAmount()` 한 곳에 있습니다.

⚠️ 그래서 **서식2 합계가 대부분 "산출 불가"로 나옵니다.** 예산 근거 문서에 근거 없는 숫자를 올리지 않으려는 것이며, AURI가 단가를 채워 주면 저절로 계산됩니다.

### 위험도 9단계

화면에는 **9단계**로 세밀하게 보여 주고, 처방 규칙표는 **3구간**을 씁니다.

### 연구원 보정 (감사 추적의 핵심)

AI 결과는 **기본값**이고 연구원이 고칠 수 있습니다. 고친 내용은 **덮어쓰지 않고 따로 보관**해서, 점수를 다시 조정해도 살아남고 "규칙이 뽑은 것 / 사람이 손댄 것"이 문서에 구분되어 남습니다.

- 점수 보정 → `edited: true` → 화면·문서에 "연구원 보정" 표시
- 시설물 수정·삭제·추가 → `auri_rx_overrides` 에 저장 → 규칙 엔진 결과와 병합

**sessionStorage 키**
- `auri_picked_location` — 선택 지점 `{addr, lat, lng, risk?}`
  ※ `risk`는 그 자리의 119 이력 종합 위험지수 `{score, level, radius, top:[{key, name, share}]}`. 이력이 없으면 `null`. 3단계 리포트와 5단계 서식1이 읽습니다.
- `auri_input_image` — 진단 입력 이미지 `{dataUrl, source}`
- `auri_diagnosis_results` — 분야별 점수 `[{key, name, score, level, findings?, observed?, notVisible?, confidence?, edited?}]`
  ※ `findings`는 항목별 판독 `[{id, ask, answer, note, risk}]`. **처방은 이 값으로 시설물을 고릅니다.** `findings` 이하는 AI 진단일 때만 있습니다(더미 점수에는 없음).
- `auri_revision_log` — AI 오독 지적 기록 `[{at, note}]` (진단서 서식1에 인용)
- `auri_rx_overrides` — 연구원이 손댄 내용 `{removed:[규칙번호], edits:{규칙번호:{...}}, added:[...]}`
- `auri_after_image` — 개선 후 이미지 (생성 모델 연결 시 저장, 진단서 서식4에서 사용)
- `auri_doc_notes` — 문서 빈칸에 쓴 글 `{칸이름:{text, ai, basis}}` (`ai`는 AI 초안 여부, 사람이 한 글자라도 고치면 false)
- `auri_project` — 지금 이 탭이 어느 저장 프로젝트에서 왔는지 `{id, title, mine, ownerName, lat, lng}`. 저장할 때 덮어쓰기 여부를 정합니다. **서버에는 저장하지 않습니다**(프로젝트 내용이 아니라 탭의 상태)
- `auri_last_user` — 이 탭에서 마지막으로 로그인한 아이디. **다른 계정으로 로그인하면 이 탭의 `auri_*` 자료를 모두 지웁니다** (앞사람 진단 결과가 보이지 않게). 로그아웃할 때도 지웁니다
- `auri_site_photos` — 현장 사진 `[{id, name, dataUrl, lat, lng, takenAt, note, manual?, field?}]` (사전진단서 4장)
  ※ `field`는 4장의 어느 절에 실을지(분야 열쇠). `manual`은 좌표를 지도에서 찍었다는 표시.
- `auri_region_stats` — 이 지점이 속한 지자체 통계 요약 `{region, label, shortLabel, inside, dong, focusTypes}` (3단계가 저장)
- `auri_prescriptions` — 최종 사업 목록 `[{id, name, note, category, score, levelLabel, kind, required?, priority, trigger?, edited?, custom?}]`
  ※ `kind`는 개입 유형(`human`/`environment`/`direct`), `required`는 협의로 반드시 넣은 유형.
  ※ `trigger`는 이 시설물을 부른 체크리스트 항목 `{id, ask, note}`. 예비 목록에서 나온 항목은 `null`.
  ※ 규칙 엔진(`auriPrescribe`)은 3단계에서 **한 번만** 돌리고 4·5단계는 그 결과를 그대로 받습니다. 단계마다 다시 계산하면 처방이 달라져 감사 추적이 깨집니다.
