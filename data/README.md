# 119 응급신고 GIS 자료

AURI에서 받은 3개년 응급신고 발생 지점 자료를 두는 곳입니다.

## 폴더 구분 — 이게 핵심입니다

| 폴더 | 내용 | GitHub |
|---|---|---|
| `data/raw/` | **AURI 원본 (SHP·래스터)** | 🔴 **절대 올리지 않음** (.gitignore 차단) |
| `data/incidents/` | 앱이 읽는 가공 결과 | 🟡 아래 조건 충족 시에만 |

## 원본을 그대로 쓰지 않는 이유

1. **보안** — 개별 신고 지점 좌표는 민감 정보입니다. 시행계획서에도 "외부 유출 불가한 지자체 내부 보안 환경"이 전제로 적혀 있습니다.
2. **브라우저가 SHP를 못 읽습니다** — Shapefile은 `.shp/.shx/.dbf/.prj` 묶음의 바이너리 형식이라, 웹 화면에서 직접 열 수 없습니다.
3. **좌표계가 다릅니다** — 국내 SHP는 보통 EPSG:5186(중부원점) 또는 EPSG:5179(UTM-K)를 씁니다. 네이버 지도는 WGS84 위경도(EPSG:4326)라 **변환하지 않으면 엉뚱한 곳에 찍힙니다.**
4. **용량** — 3개년 × 8개 분야 포인트를 전부 브라우저에 올리면 지도가 느려집니다.

## 가공 방식 — 100 × 100m 격자 집계

개별 신고 지점을 그대로 쓰지 않고 **격자 단위 건수로 집계**합니다.

```
원본: 신고 1건 = 점 1개 (민감)
  ↓
가공: 격자 1칸 = "이 칸에 N건" (집계값)
```

이렇게 하면:
- 개별 신고 위치가 드러나지 않습니다 (민감도 크게 낮아짐)
- **시행계획서의 진단 단위(100×100m 격자)와 일치**합니다
- 용량이 크게 줄어 지도가 빨라집니다

## 앱이 읽는 형식 (`data/incidents/*.json`)

```json
{
  "category": "traffic",
  "label": "교통사고 응급피해",
  "period": "2022-2024",
  "cellSize": 100,
  "unit": "건",
  "points": [
    [36.50441, 127.25887, 7],
    [36.50532, 127.25901, 3]
  ]
}
```

`points` 는 `[위도, 경도, 건수]` 입니다. 좌표는 격자 중심점이며 WGS84로 변환된 값입니다.

## 8개 분야 key

| key | 분야 |
|---|---|
| `life` | 생활손상·일상사고 |
| `violence` | 폭력상해의심 응급수요 |
| `traffic` | 교통사고 응급피해 |
| `suicide` | 자살 |
| `selfharm` | 자해·정신건강위기의심 |
| `industrial` | 산업활동 관련 응급사고 |
| `infection` | 감염의심 응급수요 |
| `fire` | 화재관련 인명피해 |

## 작업 순서

1. AURI 원본을 `data/raw/` 에 그대로 넣습니다 (폴더 구조 유지)
2. 변환 스크립트를 돌려 `data/incidents/*.json` 을 만듭니다
3. `index.html` 이 더미 좌표 대신 이 파일들을 읽습니다

**공개 여부는 AURI에 확인이 필요합니다.** 격자 집계본이라도 공개 저장소에 올려도 되는지 확인 전에는 `data/incidents/` 도 커밋하지 마세요.
